# Daily Notes — 2026-05-26 🦊

## What Happened
- **vis_stdp Always-Zero Bug Fix:** 
  - Root cause: Raw binary `stdp_spikes` were being integrated into `new_stdp_trace` in `snn_vision_fusion.py`. Because binary spikes almost never cross `V_TH_STDP` during cold-start, the trace was always zero, yielding zero for the "Camera Reality" plot row.
  - Solution: Integrated `stdp_features` (normalized continuous running trace of spikes) instead of raw `stdp_spikes`. This resolved the constant zero line in both the developmental and stable1 frontends.
- **Import Collision/Hybrid-Monster Fix:**
  - `src/stable1/snn_slam_system.py` was importing `from src.snn_vision_fusion ...`, bypassing local stable1 submodules and causing mixed developmental/stable1 imports.
  - This resulted in an `ImportError` because `src/snn_vision_fusion.py` attempted to import `VisionSTDPState` from `src/stable1/snn_vision_stdp.py` (which did not have it).
  - Solution: Rewrote absolute `from src.` imports to local/sibling imports in `src/stable1/snn_slam_system.py`.
- **macOS Metal/MPS Backend Crash:**
  - JAX crashed on Apple Silicon M5 with `UNIMPLEMENTED: default_memory_space is not supported` on the Metal backend.
  - Solution: Uncommented `os.environ["JAX_PLATFORMS"] = "cpu"` in `src/stable1/snn_slam_system.py` to match the developmental version and force CPU execution.
- **Verification:**
  - Verified compilation of all changed files (`snn_vision_fusion.py`, `snn_slam_system.py`) and ran both developmental and stable1 main scripts inside the `.venv` virtual environment successfully. No crashes.
- **Trace Wipeout & Parameter Exposure:**
  - Root cause: A hard `0.05` threshold `jnp.where(new_stdp_trace < 0.05, 0.0, new_stdp_trace)` in `src/snn_vision_fusion.py` was wiping out the faint decaying trace values when STDP firing was sparse, resulting in a flat-zero "Camera Reality" line under certain trajectory seeds.
  - Solution: Replaced the hard threshold with a simple non-negative projection `jnp.maximum(0.0, new_stdp_trace)` to robustly preserve continuous-time trace signals.
  - Parameterized the STDP episodic soft-blend ratio as a clean, global hyperparameter `STDP_MEMORY_BLEND_RATIO = 0.7` at the top of `src/snn_live_slam.py` (line 20), allowing Hao to easily adjust the memory blending weight or set it to `1.0` to completely bypass blending.
- **STDP Cold-Start Weight Decay Bug Fix (Ultimate Resolution):**
  - **Root cause:** The developmental frontend `src/snn_vision_stdp.py` introduced a continuous forgetting factor `W_DECAY_RATE = 0.99` that decayed weights exponentially every timestep (at 50Hz) even when no spikes were present. During the SLAM system's cold-start phase, sparse visual exploration meant no STDP spikes occurred, causing all synaptic weights to decay to absolute zero within 10 seconds (500 steps). This permanently killed the STDP network, keeping features and traces flat-zero forever.
  - **Solution:** Set `W_DECAY_RATE = 1.0` in `src/snn_vision_stdp.py` to disable continuous weight decay when there are no spikes, perfectly preserving weights between active spike pairing events (standard biological/neuromorphic STDP formulation).
  - **Verification:** Successfully ran the system and verified via JAX debug prints that `norm_stdp` is highly active, with features spiking continuously and trace values robustly peaking at `~0.87` in live SLAM exploration.
